# 介面語言（i18n）

App 的介面有繁體中文（`zh-TW`，預設）與英文（`en`）。第一次開 App 跟著系統語言（系統是中文就繁體中文，其他語言英文），隨時可以在「設定 → 一般 → 語言」改；開發時也可以用環境變數 `SVS_LOCALE=en` 或在設定檔寫 `"language": "en"`。

**撤回很簡單**：`packages/schema/src/i18n/locale.ts` 的 `ENGLISH_UI_READY` 改回 `false`（一行），「跟著系統」又一律是繁體中文；語言選單仍在，已經選了 English 的人不受影響。

## 怎麼運作

- 核心在 `packages/schema/src/i18n/`（不加任何套件）：`t('key', { 參數 })`、`msg('key')`、`formatDate`、`formatNumber`、`getLocale`／`setLocale`。主行程、畫面與 `packages/*` 共用同一份。
- 字串檔在 `packages/schema/src/i18n/locales/zh-TW/*.ts`（**key 的型別從這裡來**）與 `locales/en/*.ts`。每個功能一個檔案（`menu.ts`、`help.ts`…），改不同頁的 PR 不會碰到同一個檔案。`en` 的型別要求和 `zh-TW` 有**同一組 key**：少一條或多一條都編譯不過。
- key 是語意名稱（`help.step1.title`），不是中文原文。參數寫成 `{name}`，型別會檢查名稱有沒有傳；兩種語言的參數集合必須一樣（測試會擋）。
- 語言怎麼決定（主行程，`locale-service.ts`）：環境變數 `SVS_LOCALE`（非打包版才生效）＞ 設定的 `language`（`system`／`zh-TW`／`en`）＞ 作業系統語言（中文給 `zh-TW`，其他給 `en`）。主行程算好後用 `app.locale` 與 `locale.changed` 事件告訴畫面；畫面（`renderer/lib/i18n.tsx`）收到就換語言並整棵重畫。
- **測試固定用繁體中文**：e2e 的 `launchApp` 設 `SVS_LOCALE=zh-TW`，vitest 預設語言就是 `zh-TW`。原因：預設是「跟著系統」，CI 的 Linux 系統語言多半是英文，不固定的話整套測試會一起變英文。要測英文就在測試裡 `setLocale('en')`，或 e2e 用 `test.use({ appEnv: { SVS_LOCALE: 'en' } })`。
- **假語系** `en-XA`（`SVS_LOCALE=en-XA`）：英文拉長約 40%、字母換成帶記號的、前後加括號——畫面上還是正常中文的地方就是漏網的寫死字串，被截斷或爆版的地方就是英文會爆版的地方。

## 怎麼加一條字串

1. 在對應功能的字串檔加 key：`zh-TW/<功能>.ts` 與 `en/<功能>.ts` 各一條（兩邊 key 相同）。
2. 程式裡 `t('功能.key')`；有參數就 `t('功能.key', { count })`。
3. **不要在模組載入時就固定的地方呼叫 `t()`**（常數表、陣列、模組層級的 `const`）：它會把語言鎖在載入的那一刻，切換語言不會變。改成存 `msg('功能.key')`，用的時候再 `t(label)`。`msg()` 回傳的不是字串（所以直接放進畫面或當字串用會編譯不過），一定要經過 `t()`。
4. 單複數：英文要 `key_one`／`key_other` 兩條（`t('key', { count })` 自動挑），中文只要 `key_other`。
5. 日期、數字用 `formatDate`／`formatNumber`，不要寫死 `'zh-TW'`。
6. 一句話要完整：不要把「中文 + 變數 + 中文」拆成兩三條拼起來，英文語序不同；整句放一條、用 `{參數}`。

## 守門

- **ESLint 規則 `no-restricted-syntax`**（`tools/i18n/no-hard-coded-han.mjs`，`pnpm lint` 會跑）：字串、樣板字串、JSX 文字裡只要有中文字就報錯（註解不算）。例外清單在 `tools/i18n/han-exceptions.mjs`，**每一條都寫了理由**：測試與測試輔助、`locales/zh-TW/`、送給模型的提示詞（用雜湊釘住）、給 Prompt 與 MCP 用的中文名稱表、開發者工具（smoke、perf）、拿來比對舊資料的字。`tools/i18n/no-hard-coded-han.test.ts` 逐條驗證「拿掉這一條例外，就有真實檔案被擋下來」（清單裡不會留著多餘的條目），也驗證規則本身會擋、不該擋的不擋。新寫的中文字串直接紅；先想能不能改成 `t()`／`msg()`，真的是送給模型的字或開發者工具才加例外。之前用的「棘輪」（基準數字只准減少）已經拿掉。
- **型別**：`t('不存在的 key')` 編譯不過；英文少 key 編譯不過。
- **字串檔測試**（`packages/schema/src/i18n/i18n.test.ts`）：英文沒有中文字、沒有空字串、兩邊參數一致；英文介面不用 `node` 這種術語（對應中文的 `plain-words.test.ts`）。

## 搬一整個檔案的工具

`tools/i18n/codemod.mjs` 把檔案裡寫死的中文換成 `t()`／`msg()`，並寫進字串檔（可以在最新的 main 上重跑）：

```
node tools/i18n/codemod.mjs extract <功能> <檔案…> --out extract.json     # 列出要換的字串與不能自動換的地方
# 把英文寫進 translations.json：{ "中文原文": "English" } 或 { "中文原文": { "en": "English", "key": "語意key" } }
node tools/i18n/codemod.mjs apply <功能> <檔案…> --translations translations.json
```

自動換 JSX 文字、JSX 屬性、函式裡的字串與樣板字串；模組層級的字串換成 `msg()`（用的地方要手動改成 `t(…)`，型別會擋沒改的）；用 `+` 拼接、拿來比對資料的中文不動、會列出來手改。換完要 `prettier --write`，並跑 `pnpm i18n:baseline`。

## 容易漏掉的地方（PR 3 學到的）

- **字串裡夾著別的字**：`` `${名稱}（推薦）` ``、JSX 裡的 `（{x}）`、`join('、')` 這類「程式自己加的標點與連接詞」工具不會當成要翻的字，英文會留著全形標點。整句放一條（`{參數}`），清單的分隔符用一條訊息（`settings.listSeparator`）。畫面測試（`settings-english.test.tsx`）會擋英文裡的中文字與全形標點。
- **@svs/schema 自己的檔案**不能 `import … from '@svs/schema'`（循環相依）；工具會自動改成到 `i18n` 的相對路徑。
- **單複數**：`foundBooks_one`／`foundBooks_other` 是第一個真的用到的（`t('settings.foundBooks', { count })`）。中文只寫 `_other`。
- **模型卡**（`packages/providers/models/*.json`）：主要欄位是繁體中文；英文介面用選填的 `en`（`displayName`、`userNote`、`badges`）與聲音的 `labelEn`，沒填的欄位退回中文。用 `cardText(card)` 取，不要直接讀 `card.userNote`。內建卡一定要有，測試擋。
- **語言選項**：在「設定 → 一般」（`language-card.tsx`）。語言用各自的名字顯示（`LANGUAGE_NAMES`，放在 `locales/zh-TW/`，不翻譯）。
- **換語言整棵樹會重新掛上**，樹裡的狀態會歸零（包括目前在哪一頁）。要留下來的狀態記在樹外面（例如 `lib/view-memory.ts` 的目前頁）。目前沒有保留的：捲動位置、還沒存的輸入框內容。

## 畫布那一支學到的

- **載入時就執行的 `t()`**：`Array.from(…, () => t(…))` 這種選項清單、頂層的 `const X = t(…)` 會在模組載入的那一刻翻（語言還沒定、換語言也不會變）。常數表用 `msg()`，選項清單做成函式在畫的時候呼叫。`tools/i18n/module-level-t.test.ts` 會掃全 repo 擋掉。
- **別拿顯示的字當資料**：標題用「・」分段、標籤用「：」分段、拿字串去比對（`'成品接好了'`）、用中文當 `data-testid`，換成英文都會壞。分段用 `/\s*[・·]\s*/`、比對用 `messageVariants('key')`（每種語言的文字都算）、testid 另外給固定的鍵。
- **清單的分隔符**（`、`、`與`、`；`、`・`）用 `list.comma`／`list.and`／`list.semicolon`／`list.dot`，不要寫死在 `join()` 裡。
- **同一個詞在句子中間與當標題**：英文大小寫不同，句子中間的名詞用 `.toLowerCase()` 或另寫整句。
- **「中文＋變數＋中文」要整句**，連 `（至少）`、`（估算）`、`（推薦）` 這種加在後面的括號也是：用兩條整句訊息，不要 `${x}${cond ? '（…）' : ''}`。
- **畫面測試**：英文介面的 e2e（`canvas-english.e2e.ts`）掃畫面上的中文與全形標點；還沒轉的別的範圍（佇列、Claude 對話、鏡頭面板、示範模式的內容）列在 `NOT_YET` 或排除，轉完就拿掉。

## 其餘功能頁與主行程服務學到的

- **工具不認的「全形標點」**：只有標點、沒有中文字的字串（`` `${a}・${b}` ``、`` `${act}／${scene}` ``、`` `（${x}）` ``、`` `${label}：${value}` ``）工具不會抓。用 `list.dot`／`list.sentence`，或整句放一條訊息（`storyboard.actScene`、`shell.withShortcut`）。`pages-english.e2e.ts` 掃整頁的中文與全形標點，會抓到。
- **預設名稱是資料**：新增時寫進專案的名字（`新的場`、`第 N 幕`、`新的鏡頭`、匯入的那一幕）照「新增那一刻」的介面語言；之後拿它們來比對（是不是還沒寫內容、是不是預設名）要用 `messageVariants()`，換過語言也要認得（`isNewShotDescription`、`isPlaceholderName`、`isAiTurnLabel`）。
- **復原清單的名稱**照「記錄那一刻」的語言存；Claude 那一輪的名字用 `aiTurnUndoLabel()` 產生、`isAiTurnLabel()` 認。
- **模型名稱**一律經 `displayNameOf(card, fallback)`／`cardNameOf(card)`（跟介面語言），不要直接讀 `card.displayName`。
- **給模型看的提示、log、MCP 的訊息**不在這一支：留中文，PR 7 統一處理（見下面「最後一批」）。
- **單複數**：`t('key', { count })` 的訊息兩種語言都要有 `{count}`；要顯示千分位的數字（`{formatted}`）就不做單複數（`slima.wordCount`）。

## 套件（db／engine／media／providers／slima／workflows）與名稱表學到的

- **名稱表分兩份**：給人看的（景別、角度、運鏡、畫風、參考圖用途）放 `domain/labels.ts`（`shotSizeLabel()` 等，跟介面語言）；送給模型的 Prompt 與 MCP 回給 Claude 的名稱仍用原本的中文表（`SHOT_SIZE_LABELS`、`CAMERA_MOVES`…），Prompt 用 SHA-256 釘住，不隨介面語言變。畫面上不要再讀那幾份中文表（`labels.test.ts` 逐項對照繁中和舊表一字不差）。
- **zod 的訊息**在模組載入時建立，不能直接放 `t()` 或 `msg()`：寫成 `{ error: () => t('key') }`，解析資料的時候才翻（`refine`／`superRefine` 的回呼已被 module-level 檢查認成「晚一點才跑」）。
- **模組層級的常數表放 `msg()`、用的時候才 `t()`**：`NODE_INFO` 的 `title` 是 `MessageRef`（流程圖畫的時候 `t(info.title)`）。
- **AppError 的 `userMessage`** 是給使用者看的，要走 `t()`；`cause`、log、`message`（開發者看的）不翻。「找不到{what}」這類把名詞當參數的，名詞也是一條訊息（英文用小寫的 `that scene`）。
- **示範模式的內容**（`mock/json-example.ts`、拆鏡標題、示範圖標題）跟著介面語言；英文標題在單字邊界切，不切成「A cat finds a wa」。
- **英文版面看「每個選項」**：分鏡表的下拉選單欄寬要放得下最長的名稱（`Extreme close-up`、`Over the shoulder`）；`pages-english.e2e.ts` 用選單自己的字型量每一個選項。英文專用的寬度用 `getLocale()`／`html:not([lang='zh-Hant'])`，繁中維持原樣。
- **工具不認的全形標點**這次又漏了三處（`執行：…`、`「…」`、`{label}：{hint}`），都是 `aria-label` 或樣板字串；做完一塊就跑「全畫面掃全形標點」的 e2e（`canvas-english.e2e.ts` 的 `NOT_YET` 現在是空的）。
- **還沒轉（PR 7，已完成，見下面「最後一批」）**：主行程的 log、MCP 的錯誤與說明、分鏡的英文預設指南；生成佇列的任務說明裡的提示詞片段刻意不轉。

## 英文用語與文案原則（先定的，之後照著用）

文案：短、用主動句、白話；一句話只講一件事；不用「fake」「node」這類聽起來像假貨或術語的字。

專案 project・場 scene・鏡頭 shot・角色 character・地點 location・畫布 canvas・剪輯（成品那一格）Cut・分鏡 storyboard・參考圖 reference picture・首幀（第一張畫面）first frame・服務金鑰 API key・示範模式 demo mode・示範結果 sample results（不用 fake）。介面上引用另一個按鈕的名字時用同一個英文（`“New project”`）。

## 最後一批（PR 7）學到的

- **送給模型的提示詞不跟介面語言變**（刻意的）：圖片／影片／文字模型的提示詞範本、畫風與運鏡片段、拆鏡／拆大綱／整理外觀的 system prompt 都是模型讀的固定文字；改一個字，已存專案「補跑缺的」時節點快取（以輸入的雜湊當鍵）全部失效、要重花錢。它們的輸出用 SHA-256 釘住（`packages/workflows/src/prompts-golden.test.ts`、`apps/desktop/src/main/story-language-prompts.test.ts`），測試紅了就是有人動了送給模型的字。副作用：生成佇列與生成紀錄會顯示其中少數片段，英文介面也還是中文（README 有說明）。要把「顯示用的那一段」改成跟介面語言、送出的原文不變，是另一個功能（要多一個「顯示用說明」欄位），還沒做。
- **MCP 回給 Claude 的錯誤與提示是英文**；說明裡提到的「設定頁上的名字」（設定 → 服務金鑰、AI 工具連線、一般；「AI 工具的總額度」；「接成成品」「剪輯」「成品」）用 `t()` 取使用者此刻看到的名字（`apps/desktop/src/main/mcp/ui-labels.ts`），Claude 才會對英文使用者講 “Settings → API keys”。MCP 伺服器每個 HTTP 請求建一次，所以工具描述每次都用當下的語言；**說明（instructions）在連線時就定下來**，切換介面語言後，已連的 Claude 要重連才看到新語言。stdio 橋是獨立行程（沒有介面語言），訊息英文、畫面上的名字中英並列。
- **MCP 的 `what` 標籤**（`reserveSpending(ctx, 'Generate videos', …)`）只出現在給 Claude 的錯誤與訊息裡，用英文；如果哪個標籤要出現在 App 畫面（紀錄、復原清單、佇列），就改走 `t()`。
- **log 與開發者看的錯誤**（`log.*`、`new Error(…)`）寫英文，不走 `t()`。給使用者看的 `userMessage` 才走 `t()`。
- **預設分鏡準則有中英兩份**（`DEFAULT_STORYBOARD_GUIDE`／`_EN`）：沒自訂（空字串，或存的剛好是任一語言的預設）的人跟介面語言；自己改過的原樣保留，不跟著語言換。字數上限中文 4000、英文 10000（`storyboardGuideMaxChars()`）。拆鏡 system prompt 裡包著準則的框架句仍是中文。
- **給畫面用的內部鍵不要用中文**：`nodes.tsx` 的 `'吃'`／`'出'` 這種拿來當 `data-testid` 的鍵改成 `in`／`out`（規則會擋，也避免換語言壞掉）。
