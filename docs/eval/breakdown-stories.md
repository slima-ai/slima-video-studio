# AI 拆鏡：手動評估清單

換文字模型、改拆鏡的指令（`packages/workflows/src/nodes.ts` 的 `breakdownNode`）或改運鏡清單之後，
拿下面 10 句故事各跑一次「快速開始」，對照檢查表看結果。這不是自動測試——判斷好不好需要人看。

## 怎麼跑

1. 在設定頁填入文字模型要用的 Key（或打開示範模式只確認流程不報錯，示範模式的拆鏡是固定的假資料，評估不了品質）。
2. 到「快速開始」貼上故事，鏡頭數選 5、每鏡 5 秒、畫風選下表建議的那一種。
3. 只需要看「拆鏡」那一步的結果：鏡頭列表出來後就可以取消，不用等影片生成（省錢）。
4. 每個故事把結果記在下面的「結果紀錄」表。

## 檢查表（每個故事都要對一次）

| #   | 檢查項目 | 通過標準                                                               |
| --- | -------- | ---------------------------------------------------------------------- |
| 1   | 鏡頭數   | 剛好等於選的鏡頭數（不多不少）                                         |
| 2   | 每鏡描述 | 白話、看得到的畫面與動作；沒有對白、沒有「感到悲傷」這種抽象描述       |
| 3   | 故事順序 | 鏡頭連起來讀得通：有開頭、有發展、有收尾                               |
| 4   | 角色名稱 | 同一個角色在每個鏡頭用同一個名字，沒有中途換稱呼                       |
| 5   | 運鏡     | 每一項要嘛是「不指定」，要嘛是清單裡的一種；用得合理（不會每鏡都環繞） |
| 6   | 景別     | 有變化（不是 5 個鏡頭都一樣的景別）                                    |
| 7   | 畫風     | 描述不要自己加畫風字眼（畫風由後面的 Prompt 組裝統一加上）             |

## 自動化的部分

這些已經有單元測試保證，不需要人看：

- 模型輸出一定符合 Zod 格式，格式不對會附上錯誤再問一次，還是不對就回報（`generateStructured`）。
- 鏡頭數超過要求時會截斷；鏡號與每鏡秒數由程式補上。
- 運鏡只能是清單裡的 ID 或沒有指定（清單外的值視為格式錯誤）。

## 還沒做

- 角色名稱對應到角色卡：等 M4（角色卡）完成後，拆鏡會帶入既有角色名單，並在這份清單加一項「角色名稱要用角色卡上的名字」。
- 給模型的 Prompt 依 ModelCard 建議語言改寫：目前 Prompt 是中文描述加英文畫風詞，真實模型的實測結果決定要不要做（M3-7 之後評估）。
